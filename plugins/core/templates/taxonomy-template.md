# Tag 受控词表（taxonomy）

> 全项目 frontmatter `tags` 的唯一合法词源。打 tag / 审计 tag / 新增词条均以本文件为准；不在词表内的 tag 视为待归一化项。
> 「## 能力域」表格同时是 `doc-graph-health` 巡检「概念热点」维度的默认词表——维护它 = 维护巡检雷达。

## 使用原则

1. **每份文档 ≤5 个 tag**；宁缺毋滥，没有合适的就留 `[]`。
2. **不重复 frontmatter 已表达的信息**：`module`（模块归属）、`type`（文档类型）、`status` 已有字段承载，对应含义**不进 tags**（如某 sub 下的文档不打该 sub 的字面名；PRD 不打 "prd"）。
3. **tag 只承载横切检索维度**：跨模块出现的能力主题、平台归属、特殊资产标记。
4. **中文 tag 在 YAML 中加引号**：`tags: [moc, "示例词"]`。
5. **新增词条走申请制**：先在本词表对应维度添加词条（注明日期与动机），再在文档中使用；禁止即兴造词。

## 能力域

跨模块横切的业务/技术能力主题；仅当该能力不是文档所在 module 的字面主题时打。
（首列用反引号包裹 tag 名——`doc-graph-health` 按此格式机读；替换示例行为你的业务概念词。）

| tag | 覆盖含义 |
|---|---|
| `示例能力A` | 替换为你的第一个横切能力主题及覆盖含义 |
| `示例能力B` | 替换为第二个；按需增删行 |

## 平台

仅在文档明确限定单平台或平台差异是重点时打；单平台产品可删除本节。

| tag | 含义 |
|---|---|
| `示例平台` | 替换为你的平台/端名称 |

## 特殊标记

| tag | 含义 |
|---|---|
| `moc` | 导览/索引类文档（各层 overview 统一打） |
| `demo` | demo / 原型资产 |
| `external-reference` | 外部参考资料 |
