# 开发账本

> **这本记「当时为什么这么改、怎么验的」**，由人和模型在每次工作收口时手写。
>
> 同目录下的 `changelog.md` 是另一本：那是 `librarian` / `self-iteration` / `rollback`
> 三个 skill **机器追加**的变更日志（格式 `## YYYY-MM-DD <type> <summary>`），记的是
> 框架自身动作的流水。两本互不替代，都不要往对方里写。

## 怎么写一条

- 一级项固定为 `## YYYY-MM-DD · <一句话工作线标题>`，**最新的一条放在最上面**
  （收口检查只看文件里的第一条）
- 其下每个必含字段写成 `- **字段名**：内容`（冒号全角半角都认）；字段头存在即可，
  内容允许写在下级子项里
- 必含字段清单由 `.workframe-config.json` 的 `close_check.required_fields` 声明，
  默认 7 个：模块 / 背景与根因 / 改动 / 连带 / 验证 / 提交 / 遗留。想加想减改那里，
  不改这份文件

```markdown
## YYYY-MM-DD · 一句话工作线标题

- **模块**：<basic>/<sub>（涉及的都列）
- **背景与根因**：为什么要动它
- **改动**：逐文件写清改了什么
- **连带**：受影响的连带项处理情况；评估后决定不改的附一句理由
- **验证**：怎么验的、验了哪几项、**不含**哪几项
- **提交**：commit hash（先提交主体改动拿到 hash，再回来填）
- **遗留**：→ 看板任务 id，或「无」
```

## 收口检查与开关

`module-close-check` 的 `[ledger]` 项读本文件，两种红灯的判法不一样：

- **最新条目日期不在今天/昨天** → 只有在这段时间**确实有活**（相关的 git 仓里有提交，
  或工作树有改动）时才报红；全都没动过就降为提示，因为本来就没有要记的账。git 用不了、
  判不出来时按有活处理——宁可多问一次
- **必含字段缺失** → 直接报红，不看有没有活

**装机默认开启**，本文件与 `.workframe-config.json` 的 `close_check` 键由脚手架一起生成。

不想记账的项目把那个键改成空壳：

```json
"close_check": {}
```

**是留空壳，不是删键**——脚手架写配置走的是「本地缺失才写」，删掉的键下次重跑会被原样
写回；空壳则既不被覆盖，账本检查也读不到 `ledger` 而整项跳过，不影响其余八项。

跑的时点、每一项在查什么、红了怎么修，见框架仓用户文档《一轮活怎么干》。
