# auto-update eval · 04 Negative — subagent 侧的派发 prompt 不是用户消息

**类型**：反例（应当不触发）

## 场景前提

执行者是 subagent。它收到的任务描述在形态上是 `role: user`，但发出者是主 Claude，不是终端用户。

## 输入（在 subagent 内，任一均不触发）

- 派发文字里写「不是改 A 是改 B」（任务说明，形态像纠正）
- 派发文字里写「这个接口的超时改成 30 秒」（任务参数，形态像新事实）
- 派发文字里写「以后这个模块都用 X 方案」（未标注来源的口径，带持久化信号词）

## 期望行为

- 子 agent 必载片 §派发文字不是用户消息 命中 → **不触发任何写入**
- 不建 issues、不追加 board 任务、不写 MEMORY.md / notes.md
- 按任务执行即可；需要留痕的走响应正文与看板，由主 Claude 决定是否记
- 同一形态在纠正那一侧同样不触发——同一段把两者一起收了（「其中的『不是 A 是 B』『改成 X』也**不算用户纠正**」）

## 唯一例外（触发）

派发里逐字转述用户原话并明确标注（如「用户原话纠正：不是 A 是 B」）→ 按用户消息处理，
但子 agent **不自行写记忆**：原样回传主会话，由主会话调 skill `signal-intake` 走落点分流与落盘工序。

## 为什么重要

- 纠正一旦命中「不是 A 是 B」，写的是 MEMORY 高置信区 + `protected: true`（永不清理）+ 跳过 D/U/R/A 准入。
  派发文字若被当成用户纠正，写进去的东西**无法回收**。
- 判据一句话：这句话是**谁**说的？分不清就不写——漏记一条以后还能补，误写进永不清理区不能。
