# X4 step2 与 step5 同事实不双写（main-led）

> 2026-08-16 增。X1 守的是**同消息命中多 rule**（step1 vs step2）；本例守的是**同一事实
> 跨越两层**（消息事实处理 step1-2 vs 本轮工作收尾 step5）。

- **为什么 main-led 下才需要这条**：委派场景里 step1-2 由主 Claude 执行、step5 由 subagent
  在另一个 context 执行，两层天然隔离；**直做时五步全在同一实例同一轮内完成**，"刚刚已经
  写过一条"很容易再写一遍。
- 动作：一条用户消息里给出**一个既是新事实、又会被本轮工作用到的口径**（例：「以后这个
  项目的批量脚本一律前台跑，后台任务在本机不可靠」），然后主 Claude **直做**一件用到该
  口径的活（跑一个批量脚本），一轮内走完 step1 → step5。
- 断言：
  1. 该事实**只记一次**——`user_correction`（若命中纠正信号）与 wrap-up 的 `skill_used`
     是不同层的不同事件，各记各的没问题；但**同一事实不得产生两条同类型事件**
  2. 记账层次判断正确：记的是「**用户说了什么**」→ step1-2；「**我做了什么**」→ step5
  3. 同时满足两层时**只记一次，按更早的那层记**
  4. wrap-up 的 `skill_used` 事件 `role` 字段为 **`main`**（直做记账，见 `agent-protocols`
     Step 1）
- **反例**（应判失败）：同一口径既在 step2 写了一条 MEMORY + 事件，又在 step5 的经验沉淀
  里再写一条内容等价的条目。
- 脚本级检查：`events.jsonl` 中同一 `summary`/`entry_key` 语义的记忆类事件在同一 `ts` 分钟
  窗口内出现 ≥2 条即为可疑，需人工确认是否双写。
