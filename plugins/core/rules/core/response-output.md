# 响应输出规范（全局生效）

> 此文件由 Claude Code 运行时自动加载（`.claude/rules/` 系统能力），所有 Agent 无需引用即生效。

## 核心原则：响应消息优先于文件写入

Agent 执行分析/设计/审计/评估任务后，必须遵循以下顺序：

1. **先在响应消息中呈现完整内容**（结论、草稿、报告全文）
2. **等待用户确认任务完成后再写入文件**（specs 文档、策略文件等）
3. **收尾归档（日志、看板更新）最后执行**

**⚠️ 禁止**：用"结果已写入 XXX 文件"代替实际内容输出。

## 执行过程中的自然澄清

遇到以下情况，**在继续执行前先提问**，不要假设：

- 已提供的信息不足以满足最佳的任务处理和输出
- 任务描述存在多种合理解读
- 发现与现有文档/规范有重要冲突
- 关键决策点有多个方向且影响后续较大

提问方式：用自然语句，一次最多提出 1-2 个关键问题，并提供几个建议选项；不要一次性批量罗列疑问清单。

## 选择题式澄清必须使用 AskUserQuestion 工具

**硬约束**：当向用户抛出**选择题式澄清问题**（即已有候选选项 A/B/C 让用户挑选的问题）时，**必须优先调用 `AskUserQuestion` 工具**渲染交互选项卡，而不是在纯文本消息里列 A/B/C 让用户手动敲字回复。

**适用场景**：
- 需求范围二选一 / 多选一
- 技术方案候选比较
- 验收标准粒度选择、优先级裁决、命名风格选择等

**不适用场景**（仍然用自然语句提问）：
- 开放式问题（例如"你希望这个功能支持哪些场景？"）
- 需要用户填写具体数值/名称/描述的问题

**复杂内容确认（硬约束）**：被确认对象是表格 / 多行示例 / 代码块 / 结构预览等复杂内容时，必须**先在响应正文中独立完整展示**，AskUserQuestion 的选项只做轻量判断（如"符合，按此执行 / 需调整"）；**option preview 不承载关键信息**——部分客户端对 preview 渲染不全，会导致确认空转，preview 只放可有可无的辅助摘要。

**工具加载提示**：`AskUserQuestion` 在部分会话中以 deferred tool 形式出现，调用前如报 schema 未加载，需要先用 `ToolSearch` 以 `select:AskUserQuestion` 加载其 schema，再正常调用。

**Fallback 规则**：若当前运行时既无 `AskUserQuestion` 也无 `ToolSearch`（极少数受限环境），**退化为自然语言澄清**——在响应正文中清晰编号列出 A/B/C 选项 + 推荐项 + 简短理由，请用户回复编号或选项名。fallback 不阻塞任务执行；不要因为工具不可用而拒绝继续。

**主 Claude 转述 subagent 问题时同样遵守**：若 subagent 返回的内容中含有选择题式澄清（纯文本 A/B/C 列表），主 Claude **必须用 AskUserQuestion 重新包装**后再呈现给用户，不能直接把纯文本选项原样贴出。

## 确认信号识别

完成输出后，等待用户确认当前任务完成后，再执行文件写入。**关键边界**：用户回应是"补充事实/参数"还是"否定方向 / 改写结构 / 要求重做"，决定是否需要二次确认。

**视为确认（可直接合并并写入）**：
- 明确批准词：例如确认、好的、可以、没问题、写吧、y、yes、行、方案ok
- **补充事实 / 补充参数**：用户提供新的具体数据点、字段、参数、示例数据，**且未否定当前草稿的整体方向和结构** → 合并后直接写入
  - 例："优先级改 P1 而不是 P2"、"再加上权限校验字段"、"这个表名叫 user_session 不是 sess"

**不视为确认（必须重新展示 + 二次确认）**：
- 用户发出与当前草稿无关的新任务指令（暂存当前草稿，执行新任务）
- 用户**否定当前方向 / 要求改写结构 / 要求重做** → 先修改，重新展示完整草稿，再等用户二次确认
  - 例："这个思路不对，换一种"、"重新写一版"、"AC 重新拆"、"整段重写"
- **歧义情况**（介于"补充"和"改写"之间）：默认走二次确认路径，宁多一轮不少一轮

判断口径：补充 = 在不动骨架的前提下加细节；改写 = 改骨架/方向。前者直接合并，后者必须二次确认。

## 响应消息的结构建议（非强制模板）

根据任务类型灵活调整，建议包含：

- **核心结论**：1-2 句话总结
- **主要内容**：完整分析/草稿/报告正文
- **待确认事项**（如有）：提供主要内容后，再向用户提问确认，提供备选建议

## 例外：无需等待确认直接执行的操作

以下为系统维护类操作，低风险，直接执行：

- `board.yaml` 状态字段更新（`status` 字段变更）
- `MEMORY.md` / `notes.md` 知识条目追加
- `summary:` 统计数字重算（**SessionEnd hook 自动 + SessionStart drift check 兜底**；用户也可显式调用 `workframe-recompute-board-summary` 命令手工触发，详见 `task-management` SKILL.md）
