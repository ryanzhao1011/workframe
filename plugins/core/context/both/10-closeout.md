# 收口纪律

**收口 = 你准备说「这件事做完了」的那一刻**——提交前、交付前、把任务标为 `completed` 或 `pending_qa` 前。本段管那一刻之前必须做完的事，只管**该不该做、做到什么程度**；**怎么做**的工序在对应 skill 里。

## 改动闭环

1. **定位影响面**：动手前确定改动落在哪个模块，读它的 `submodule.yaml`（`code_paths` 圈定受影响文件、`api_dependencies` 列跨模块依赖）与该模块 overview
2. **连带清单逐项过**：上一步圈出的连带项逐个检查；评估后决定不改的写一句理由，不许静默跳过
3. **stale 标记必处理**：被标记过期的模块文档收口前更新或说明；双归属文件两个模块都复查
4. **机器验收全绿**：见下一节
5. **记账**：这次改了什么、为什么改、怎么验的，写进项目账本

**落到 skill 的三处工序**：写或改 markdown 文档前 → 调 skill `document-norms`（文件放哪儿查 §1）；模块文档被标过期 → 调 skill `code-to-doc` 刷 current-state 与基准；账本是 `.workframe-config.json` 的 `close_check.ledger` 指向的那份，必含字段以同处的 `close_check.required_fields` 为准。

**「命中」怎么判**：改动的文件落在某模块 `code_paths` 的展开面内就算命中，与改了几行、是否只改注释无关；删掉一个被 glob 覆盖的文件同样算。命中即须刷该模块的基准与文档，「评估后不刷」只留给改动文件不在任何清单内的场景。

**与「外科手术式改动」的边界**（`technical-design` skill 的工程纪律 reference，原则 3）：**两者不冲突**。它禁的是与本次改动**无关**的顺手清理，本节要求的是**同一事实**的同步。判据是这处待改点与你本次要解决的问题有没有因果关系。

## 跑什么闸

| 层 | 跑什么 | 判据 |
|---|---|---|
| 框架层（每个项目恒有） | `workframe-doctor`、`workframe-module-close-check` | 两者全绿才收口 |
| 项目层（有则跑） | 项目自己的 lint / 类型检查 / 测试套件 | 全绿；没有就明说没有 |

- **doctor 验的是装机健康，不验业务正确性**——它全绿只说明框架装对了，不说明你的改动是对的
- 项目层没有任何自动化检查时，写「本项目无自动化测试，本次靠 X 人工验证」，**别写「已验证」**（完整口径见 §陈述可证伪）
- 闸绿不等于收口完成：闸只覆盖它写明覆盖的那部分，其余靠上一节的清单与下一节的双检

## 谁签发这次收口：四段闸门

**默认 = @qa 完整验证。** 不是「首轮特别严」，而是**没有任何独立视角看过的东西，默认就该被独立看一次**——首轮天然落在这里，因为它天然没有前轮结论。四段依次算，三段机器可算（`signoff_tier_check.py`），模型出力的是通行证那段的论证、地板那段的爆炸半径取值（机器只读它、不判它），以及封顶那段机器判不了的否决项：

| 段 | 问什么 | 谁算 | 效果 |
|---|---|---|---|
| ① 默认起点 | —— | 机器 | 恒 `@qa 完整验证` |
| ② **通行证** | 有没有覆盖**本轮 delta** 的独立结论？ | 模型论证，机器只验声明格式与 hash 可解析 | **唯一能往下降的东西**；没有就停在默认档 |
| ③ 地板 | 爆炸半径卡住最低能降到哪 | 机器读三问结果 | 档 4 降不下去／档 3 最低到轻签注／档 1-2 可到自签 |
| ④ 封顶 | 命中六条否决项之一？ | 机器为主 | 命中即到用户，**无论前三段算出什么** |

- **通行证来自别的任务时允许继承，但必须显式声明：哪个任务、哪一轮、覆盖了什么。** 这道门被真实绕过过一次，从此暗门改明路且可核。
- **爆炸半径只往上抬，不发通行证。** 把它接成通行证等于按机器覆盖率**正**相关分配人的监督，而正解是**负**相关——「机器发现不了」是它更该被人看的理由，不是更不该。
- **切片锚定为「上一个签发点到现在」的 diff，不是整个任务。** 不锚死的话同一份工作能被合法算出两个相反档位，**而切片的人正是受益的人**。
- **机器只验通行证的格式，验不了「这份独立结论真的覆盖了本轮 delta」。这是本流程最软的一环**，且它出过错——出错形态正是「上轮结论以为覆盖了、实际没有」。
- **自签档默认开启**（`.workframe-config.json` 的 `signoff.self_signoff_enabled` **缺键即 true**）。要求更严的项目显式写 `false`，写了之后 `pending_qa → completed` 仍须实际调度 @qa。
- **默认开启是被知情接受的取舍，它的代价必须一起读**：①**Codex 门下这道把关实测不起作用**（matcher 命中，但 Codex 改文件走 `apply_patch`、载荷不带文件路径，把关脚本直接放行）——那一门下的把关**按不存在对待**、四段举证纯靠自觉；**别把 Codex 门下的签发读成「已有把关」**；②用 shell 命令（脚本／`sed`／重定向）改看板时它**只提示不拦**；③散文形态的既有签注不进把关面。**这三条不是「某种输入下失效」，是把关面本来就不覆盖的地方**——别把它的绿读过头。

**降到自签或轻签注时，`qa_signoff` 必须写四段举证**（① 准入凭据 ② 验了什么 ③ 没验什么＋为什么 ④ 未独立复核的部分），并向 `<state>/events.jsonl` append 一行：

```json
{"ts":"<ISO-8601>","type":"self_signoff","task_id":"<TASK-ID>","tier":"自签","same_party":true,"radius":2,"passport":true,"role":"main"}
```

- **`same_party` 必含**：实现方与签发方是否同一方。允许同一方时这是唯一的补偿控制——它把「成色最低的那种」从散文变成可分组的字段；缺了它，事后问题率就只剩一个混合池。
- **④ 的判据是二元口诀**：本轮有没有第二个 context 从零看过同一份产出？**没有 → ④ 写「全部」**，然后列出你据以自信的机器证据。实现与签发同为主会话时**恒命中「没有」**。
- **② ③ 的恒真自查**：落笔前问一句——这条排除的是真实风险面，还是本次范围内**恒真**的命题？恒真即删。恒真的排除读起来谨慎、信息量为零，还会挤掉真正该披露的那条。
- **这条事件由被审计者自己写，输入不可信**，只能做趋势不能做证据。看板那侧由 hook 重算把关，那道闸挡的是**档位写松**，挡不住「干脆不写这条事件」。

**六条否决项**（命中任一 → 用户拍板）：① **结构化条目删除**（列表项／表格行／YAML 序列项的 `-` 行无对应 `+` 行；**第一顺位仍是「别删，改 supersede」，不是「找用户批」**）② **发版动作**（推 main／打 tag／改版本号／改对外 CHANGELOG 已发布段）③ **判定命题被推翻** ④ **产品决策**（影响所有下游的 schema、warn/error 取舍）⑤ **两个独立结论冲突** ⑥ **受保护资产的契约变更**（非表述变更）。**只有 ①⑥ 有机器面**，③④⑤ 纯模型判、②只判得了版本号字段。

### 否决项 6 的清单与判法

**入选判据（两条同时满足才封顶）**：**(a) 人手改的**——机器生成或同步的派生物不算；**(b) 改错了会静默扩散或难回收**——渲染进每会话必载面／写进永不清理区／让框架整体不加载。

| 路径 | 为什么在 |
|---|---|
| `CLAUDE.md` | 每会话必载 |
| `AGENTS.md` | 每会话必载 ＋ 两扇门都读 ＋ 人手改 |
| `.claude/agents/**` | 改的是角色契约 |
| `.claude/settings*.json` | 改错框架整个不加载 |
| `.workframe-config.json` | 项目身份与运行档位 |
| `shared/MEMORY.md` | 应用层最高权威 ＋ 永不清理 |

**明确排除，写出来是因为「没列」与「判过不该列」在读者眼里同形**：`context/**` 是**框架仓资产**、随插件分发而不由项目手改，不满足 (a)；`.workframe/state/**`（运行态，hooks 与 system skill 写）与项目 skills `.claude/skills/**`、`.agents/skills/**`（按需调用、当轮可见，其发版顾虑由否决项 2 承接）同理不在内。`.claude/rules/**`（含 `local/`）**不在本表内**——成因**不是**「它随机制消失了」（那些是项目自己的文件，框架从来没拥有过），而是**框架不再推荐这个落点、用不用它是项目自己的选择**；**2026-09-10 由用户拍板不纳入保护面**。⇒ 仍在用该能力的项目，其项目 rules **无封顶、无直写保护**。**这是永久状态，不是等某个批次收尾的窗口期。**

**判法 = 路径触发 ＋ 模型判契约还是表述，方向钉死：拿不准一律算契约变更。** 误判只能往严跑（多问用户一次，代价有界可观测），不能往松跑（静默绕过用户闸）。所以机器把路径命中报成**待裁决**而不是「未命中」——**裁决为表述变更之前，本次判定不是终局**。

> **本表与 §受保护资产清单 是两张表，各管各的，不得互相代读。** 那张管「信号入账规则自己不许直接写哪些文件」，本表管「签发档位何时封顶到用户」。**本表是它的真子集**——差集里的路径（`.claude/skills/**`、`.agents/skills/**`、`projects/proposals/**`、`README.md`、`LICENSE` 等）**仍受那张表约束**，只是不再自动封顶。

### 谁实现：与谁签发是两条互不干涉的轴

**缺省主会话直做**；**需独立 QA ／ 工具隔离 ／ 多领域长任务 ／ 依赖 agent 专属上下文** 四类必须委派。这不是新规则，是「未指定角色时按任务性质自行决定直做还是委派」那条既有规则在签发这一格上的实例——它形状 fail-safe（列的是「必须委派」，直做是缺省），且第一项「需独立 QA」直接推出「完整验证档的实现方不是主会话」。

**别把两条轴缠在一起**：「谁实现」判完就结束，不影响「谁签发」；反之亦然。

## 验证纪律

**双检**：每项完成后做两次，**角度必须不同**。

| | 站在谁的角度 | 走什么路径 |
|---|---|---|
| 一检 | 构建者，正向 | 改动点本身：语法 → 真实数据实测 → 对照清单逐项确认落盘 |
| 二检 | 审计者，反向 | 端到端 + 边界矩阵（空 / 缺失 / 异常格式 / 极端值），换关键词重新扩范围 |

- **一检思路复用则二检等于没做**：二检必须换关键词、换入口、换检查顺序，否则只是把一检重跑一遍
- **边界**：二检**可以**由同一个人做（换角度即可），但**不能替代**独立审查——两者串联，不是二选一

### 新增检查必须用它自己的失败方式打一遍

「写完了但从没真正执行过」的检查，与通过长得一模一样。

- **突变粒度必须细于断言粒度**：一次只毁掉断言的一个组成部分。粗粒度突变报红只证明红来自这一整块，证不出被它掩盖的每条子断言各自是活的
- **判据一句话**：你的探针能不能分辨出是哪一半在起作用？不能，就还没验过
- **出口**：构造不出失败态时（依赖外部环境或时序）登记它并写明为什么，**不许默默跳过**——跳过和做过在终端里同形，正是这条要防的东西

### 交给模型的判断点必须有明确标准

判据表 / 枚举 / 二元口诀 / 示例，任选其一，**禁止裸交「模型自行判断」**——同一句话在不同会话里会落到不同的一侧。

**边界**：确实写不出标准时，评估偏移是否 fail-safe（偏了会红还是会静默放行），并说明有无代码闸兜底；不评估就交出去才是违规。

## 同一事实的多个表现层

**跨多个文件的同一事实：找出唯一实现，其余改成引用；两处手写必漂。**

- 做不到唯一实现时（各表现层形态不同），改完一处后 grep 其余全部表现层，同一批改完
- **「全部表现层」说的是层，不是文件**：同一口径常同时活在必载纪律／`CLAUDE.md`／skill 正文／角色记忆／用户文档，**甚至分属不同的仓**。只在你正在改的那一层里 grep，另外几层会原样留着，而读到它们的人照旧按旧口径做。**落笔前先列出这条口径有几层，再逐层查**——两次实证都是「本层全对、别层全漏」
- **改之前先找齐，写之前也先找齐**：新写一个判定式前先 grep 同契约的既有实现，存在则复用，或写明为何不复用
- 两份实现是**交叉关系**（各自携带对方没有的知识）时，正解是**取并集**，不是挑一份替换掉另一份
- **引用型记录必须在被引用对象存在之后写**：账本里的提交 hash、文档里的基准 commit，都要先提交拿到 hash 再写记录，否则落笔的是机器无法追溯的指代

## 收口时的归位

干活时怎么写都行，**收口时提炼归位，原始过程档从工作区删除**——版本历史永远可查。**删之前先提交一次**建立备份点，再删。跨会话的执行跟踪文档完成使命后同样按此表提炼。

| 内容 | 落点 |
|---|---|
| 还没做完的 | 任务看板 |
| 「为什么这么设计」 | 该模块的 decisions 记录 |
| 「哪天做了什么、怎么验的」 | 项目账本 |
| 可复用的方法、踩过的坑 | 按 `librarian` §2b 落点分层决策定（**判定是确定性的先考虑落机器闸**；其余在必载层 / skill / 角色记忆 / notes 之间选）|
| 都不属于 | 没有长期价值，不留 |

**退役不留墓碑**：运行时资产（skill 正文 / 注入片 / 模板正文）只写当前生效的机制，不写「已废弃 X」「不再需要 Y」，也不带内部迭代编号——历史归账本与版本历史。

**边界**：能力边界陈述不是墓碑。「这道闸只覆盖 A、不覆盖 B」必须保留——那是可证伪纪律要求的，删掉它等于把一个已知缺口变成暗坑。
