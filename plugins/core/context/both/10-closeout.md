# 收口纪律

**收口 = 你准备说「这件事做完了」的那一刻**——提交前、交付前、把任务标为 `completed` 或 `pending_qa` 前。本段管那一刻之前必须做完的事，只管**该不该做、做到什么程度**；**怎么做**的工序在对应 skill 里。

## 改动闭环

1. **定位影响面**：动手前确定改动落在哪个模块，读它的 `submodule.yaml`（`code_paths` 圈定受影响文件、`api_dependencies` 列跨模块依赖）与该模块 overview
2. **连带清单逐项过**：上一步圈出的连带项逐个检查；评估后决定不改的写一句理由，不许静默跳过
3. **stale 标记必处理**：被标记过期的模块文档收口前更新或说明；双归属文件两个模块都复查
4. **机器验收全绿**：见下一节
5. **记账**：这次改了什么、为什么改、怎么验的，写进项目账本

**落到 skill 的三处工序**：写或改 markdown 文档前 → 调 skill `document-norms`（文件放哪儿查 §1）；模块文档被标过期 → 调 skill `code-to-doc` 刷 current-state 与基准；账本是 `.workframe-config.json` 的 `close_check.ledger` 指向的那份，必含字段以同处的 `close_check.required_fields` 为准。

**「命中」怎么判**：改动的文件落在某模块 `code_paths` 的展开面内就算命中，与改了几行、是否只改注释无关；删掉一个被 glob 覆盖的文件同样算。命中即须刷该模块的基准与文档，「评估后不刷」只留给改动文件不在任何清单内的场景。

**与「外科手术式改动」的边界**（`technical-design` skill 的工程纪律 reference，原则 3）：**两者不冲突**。它禁的是与本次改动**无关**的顺手清理，本节要求的是**同一事实**的同步。判据是这处待改点与你本次要解决的问题有没有因果关系。

## 跑什么闸

| 层 | 跑什么 | 判据 |
|---|---|---|
| 框架层（每个项目恒有） | `workframe-doctor`、`workframe-module-close-check` | 两者全绿才收口 |
| 项目层（有则跑） | 项目自己的 lint / 类型检查 / 测试套件 | 全绿；没有就明说没有。跑多大范围按项目判据声明（本地检查 / CI 检查 / 回退全量的条件），没声明就全量；不凭文件后缀豁免 |

- **doctor 验的是装机健康，不验业务正确性**——它全绿只说明框架装对了，不说明你的改动是对的
- 项目层没有任何自动化检查时，写「本项目无自动化测试，本次靠 X 人工验证」，**别写「已验证」**（完整口径见 §陈述可证伪）
- 闸绿不等于收口完成：闸只覆盖它写明覆盖的那部分，其余靠上一节的清单与下一节的双检

## 谁签发这次收口：两类签发

**先问一句：这次改动错了，主会话自己验得出来吗？** 验得出来 → **主会话自理**；验不出来 → **需要独立验证**。总原则是保证效果的同时，尽可能减少不必要、冗余的步骤。否决项命中则不论哪一类都交用户拍板（见下文六条）。

**需要独立验证**——命中任一条（拿不准按第 3 条算命中）：

1. **改的东西本身负责判断对错**：闸、校验、测试、签发／放行逻辑、评分标准、自查清单——错了会静默放行，拿它自己验它发现不了
2. **影响核心链路，且出错难发现或难回收**：每会话加载的东西（注入纪律、hook 链路）、装机与升级链路、分发给所有用户的数据格式或契约
3. **主会话自己拿不准**：方案里有明显没把握的地方，或改动面大到一个上下文顾不过来

三条都不命中 → **主会话自理**：要不要验、验到什么程度由主会话自行评估，签注写清验了什么、没验什么。

- **验证方不限**：与实现方没有共享上下文的任一方——新 @qa、另一个模型的 CLI、外部 agent；在别的模型里实现、拉 Claude 来验证同样成立。继承实现上下文的派发形态（如 CC 的 fork）不算
- **验几轮由模型自评**：只修真实问题（影响实际使用，或会造成假绿且没有其他兜底）；防御性、罕见形态、措辞类的问题一行能改就顺手改，否则写一句不改的理由，不为它们返工；通常一轮验证、修完后对增量复核一次；仍有关键问题 → 停下重审方案或交用户——轮次上限不是收口理由
- **类别由模型判，机器不判**：把该独立验证的判成自理，没有任何机器面会说话
- **自签开关**：`.workframe-config.json` 的 `signoff.self_signoff_enabled` **缺键即 true**；显式写 `false` ⇒ 研发任务一律按「需要独立验证」签发

**签注**：研发任务转 `completed` 时写在 `qa_signoff`，字段与看板把关 hook 的检查项见 skill `task-management` §签发块 schema（签发要动看板，动看板前必调它）。

- **「没验什么」的恒真自查**：落笔前问一句——这条排除的是真实风险面，还是本次范围内**恒真**的命题？恒真即删。恒真的排除读起来谨慎、信息量为零，还会挤掉真正该披露的那条
- **hook 的绿别读过头**：它只查签注格式、按切片两端自己重算否决项；类别判得对不对、验证方写得真不真、切片有没有漏声明改过的仓，都不判。Codex 门下经 `apply_patch` 改看板也会判、违规同样 exit 2，但 Codex 怎么处置它没验过；shell 改看板只报不拦，收口检查不查签注格式

**六条否决项**（命中任一 → 用户拍板，不论签发类别）：① **结构化条目删除**（列表项／表格行／YAML 序列项的 `-` 行无对应 `+` 行；**第一顺位仍是「别删，改 supersede」，不是「找用户批」**）② **发版动作**（推 main／打 tag／改版本号／改对外 CHANGELOG 已发布段）③ **判定命题被推翻** ④ **产品决策**（影响所有下游的 schema、warn/error 取舍）⑤ **两个独立结论冲突** ⑥ **受保护资产的契约变更**（非表述变更）。**只有 ①⑥ 有机器面**，③④⑤ 纯模型判、②只判得了版本号字段。

### 否决项 6 的清单与判法

**入选判据**：人手改的（派生物不算）**且**改错了会静默扩散或难回收。

| 路径 | 为什么在 |
|---|---|
| `CLAUDE.md` | 每会话必载 |
| `AGENTS.md` | 每会话必载 ＋ 两扇门都读 ＋ 人手改 |
| `.claude/agents/**` | 改的是角色契约 |
| `.claude/settings*.json` | 改错框架整个不加载 |
| `.workframe-config.json` | 项目身份与运行档位 |
| `shared/MEMORY.md` | 应用层最高权威 ＋ 永不清理 |

**明确不在内（永久状态）**：`context/**`（框架资产，不由项目手改）、`.workframe/state/**`（运行态）、项目 skills `.claude/skills/**`、`.agents/skills/**`（发版顾虑由否决项 2 承接）、`.claude/rules/**`（含 `local/`；框架不再推荐这个落点，用户拍板不纳入——仍在用它的项目，其 rules **无封顶、无直写保护**）。

**判法 = 路径触发 ＋ 模型判契约还是表述，拿不准一律算契约变更**（误判只许往严跑）。机器把路径命中报成**待裁决**——裁决为表述变更之前，本次判定不是终局。

> **本表与 §受保护资产清单 各管各的，不得互相代读**：那张管信号入账不许直写哪些文件，本表管签发何时交用户拍板。本表是它的真子集——差集里的路径（`.claude/skills/**`、`.agents/skills/**`、`projects/proposals/**`、`README.md`、`LICENSE` 等）仍受那张表约束，只是不自动封顶。

### 谁实现：与谁签发是两条互不干涉的轴

**缺省主会话实现**；派子 agent 的情形与派工写法见主会话协议 §派发子 agent（子 agent 不再派发）。**别把两条轴缠在一起**：「谁实现」判完就结束，不影响「谁签发」；反之亦然。要独立验证时派出去的是**验证方**——禁的是同一个上下文既实现又验证，不是主会话实现。

## 验证纪律

**双检**：决定要验的每一项做两次，**角度必须不同**（要不要验、验多深，按 §谁签发这次收口 与 skill `test-case-design` 的四档判）。

| | 站在谁的角度 | 走什么路径 |
|---|---|---|
| 一检 | 构建者，正向 | 改动点本身：语法 → 真实数据实测 → 对照清单逐项确认落盘 |
| 二检 | 审计者，反向 | 端到端 + 边界矩阵（空 / 缺失 / 异常格式 / 极端值），换关键词重新扩范围 |

- **一检思路复用则二检等于没做**：二检必须换关键词、换入口、换检查顺序，否则只是把一检重跑一遍
- **边界**：二检**可以**由同一个人做（换角度即可），但**不能替代**独立审查——两者串联，不是二选一

### 新增检查必须用它自己的失败方式打一遍

「写完了但从没真正执行过」的检查，与通过长得一模一样。

- **突变粒度必须细于断言粒度**：一次只毁掉断言的一个组成部分。粗粒度突变报红只证明红来自这一整块，证不出被它掩盖的每条子断言各自是活的
- **探针自己也要验**：改坏、跑测试、恢复，每步亲眼确认生效（那一行确实变了、用例确实被执行、恢复后与基线一致），不凭退出码推断；结果出乎意料时，先排除「没走到 / 观测时点不对」，再判被测对象
- **期望值不得取自被测对象**：用它导出的常量、同一份实现或它读取的那份文档当期望，两边一起错时照样绿
- **判据一句话**：你的探针能不能分辨出是哪一半在起作用？不能，就还没验过
- **出口**：构造不出失败态时（依赖外部环境或时序）登记它并写明为什么，**不许默默跳过**——跳过和做过在终端里同形，正是这条要防的东西

### 交给模型的判断点必须有明确标准

判据表 / 枚举 / 二元口诀 / 示例，任选其一，**禁止裸交「模型自行判断」**——同一句话在不同会话里会落到不同的一侧。

**边界**：确实写不出标准时，评估偏移是否 fail-safe（偏了会红还是会静默放行），并说明有无代码闸兜底；不评估就交出去才是违规。

## 同一事实的多个表现层

**跨多个文件的同一事实：找出唯一实现，其余改成引用；两处手写必漂。**

- 做不到唯一实现时（各表现层形态不同），改完一处后 grep 其余全部表现层，同一批改完
- **「全部表现层」说的是层，不是文件**：同一口径常同时活在必载纪律／`CLAUDE.md`／skill 正文／角色记忆／用户文档，**甚至分属不同的仓**。只在你正在改的那一层里 grep，另外几层会原样留着，而读到它们的人照旧按旧口径做。**落笔前先列出这条口径有几层，再逐层查**——两次实证都是「本层全对、别层全漏」
- **改之前先找齐，写之前也先找齐**：新写一个判定式前先 grep 同契约的既有实现，存在则复用，或写明为何不复用
- 两份实现是**交叉关系**（各自携带对方没有的知识）时，正解是**取并集**，不是挑一份替换掉另一份
- **引用型记录必须在被引用对象存在之后写**：账本里的提交 hash、文档里的基准 commit，都要先提交拿到 hash 再写记录，否则落笔的是机器无法追溯的指代

## 收口时的归位

干活时怎么写都行，**收口时提炼归位，原始过程档从工作区删除**——版本历史永远可查。**删之前先提交一次**建立备份点，再删。跨会话的执行跟踪文档完成使命后同样按此表提炼。

| 内容 | 落点 |
|---|---|
| 还没做完的 | 任务看板 |
| 「为什么这么设计」 | 该模块的 decisions 记录 |
| 「哪天做了什么、怎么验的」 | 项目账本 |
| 可复用的方法、踩过的坑 | 按 `librarian` §2b 落点分层决策定（**判定是确定性的先考虑落机器闸**；其余在必载层 / skill / 角色记忆 / notes 之间选）|
| 同一段脚本 / 环境配置第二次现写 | 留存进仓成为工具，不随过程档删除 |
| 都不属于 | 没有长期价值，不留 |

**退役不留墓碑**：运行时资产（skill 正文 / 注入片 / 模板正文）只写当前生效的机制，不写「已废弃 X」「不再需要 Y」，也不带内部迭代编号——历史归账本与版本历史。

**边界**：能力边界陈述不是墓碑。「这道闸只覆盖 A、不覆盖 B」必须保留——那是可证伪纪律要求的，删掉它等于把一个已知缺口变成暗坑。
