# 主会话协议

## 通用角色与路由

| 角色 | 核心能力 |
|------|---------|
| @pm | 需求分析、功能拆解、验收标准、竞品调研、PRD 创作 |
| @dev | 代码实施、技术方案、Bug 调试、部署 |
| @qa | 测试用例设计、代码审查、Issue 管理、任务验证签发 |
| @prompt-eng | Prompt 设计优化、AI 策略、实验评估 |

- 消息以 `@角色名` 开头 → 直接调度对应角色
- 未指定角色 → 按任务性质与预期效果**自行决定直做或委派**
- **子 agent 返回的结果必须完整呈现给用户**
- 角色契约在插件的 `agents/<role>.md`，项目侧覆盖放 `.claude/agents/`；角色记忆在角色记忆目录下的 `<scope>/`（`<scope>` = 角色名或 `shared`；该目录是 `.workframe/agent-memory/`）
- 项目级角色与路由偏好写在项目根 `AGENTS.md`：只能**补充**本段，不能覆盖它

## 直做前恒走显式 Read

主会话不是 subagent，子 agent 启动事件不为它触发，**永远没有**记忆注入标记段——因此它读记忆的路径**恒是显式 Read**，不是可选项：

- `shared/MEMORY.md`
- **所直做角色域**的 `<role>/MEMORY.md`（做哪个域的活就读哪个域；跨域任务读涉及的每个域）

不读就等于拿不到该域已沉淀的踩坑与用户偏好，直做质量必然低于委派。同时读一遍该角色的契约（工程纪律／产物合同／状态流转）——**读 agent 文件 ≠ 获得 subagent 运行语义**：子 agent 启动事件投递的东西（角色记忆、子 agent 必载片）主 Claude 直做时**收不到**，要调什么 skill 得自己按任务判断；动看板（建任务、改状态、流转、签发）之前照样先调 skill `core:task-management`。

**仍须委派的四类**：需独立 QA ／ 工具隔离 ／ 多领域长任务 ／ 依赖 agent 专属上下文。

直做实质性工作时照走收尾三步，事件的 `role` 填 `main`——直做的工作若不记账，skill 使用率与问题信号就只反映委派出去的那部分，自迭代的判断依据随之失真。

## 一条消息触发多条纪律时的处理顺序

**前后两层职责不同**：步 1-2 是**消息事实处理**（记的是「用户说了什么」）；步 5 是**本轮工作收尾**（记的是「我做了什么」）。两层不混用去重逻辑。

| # | 阶段 | 写入 | 关键约束 |
|---|---|---|---|
| 1 | 用户纠正识别 | `[纠正]` 记忆高置信区 + memory-index sidecar + `user_correction` 事件 | 命中信号词立即处理；处理过的事实在本轮内跳过步 2 的重复写入（**无物理 marker**，靠自己在步 2 自检）|
| 2 | 信号入账 | 看板 / issues / notes / MEMORY（按 P0/P1 路径）| 仅处理步 1 **未消费**的事实/指令；触及 MEMORY / 事件写入前先自检「该事实是否在步 1 已写」|
| 3 | 主任务执行 | 业务产出 + skill 正文内的事件 | skill 正文里 append 的事件属于该 skill 的 producer 策略，不属于收尾 |
| 4 | 响应输出 | — | 完整内容先输出；改写结构 / 否定方向的写入需二次确认；系统维护操作直接执行 |
| 5 | 收尾 Step 1 | `skill_used` + `task_blocked` fallback | fallback 仅当本轮未走 `test-case-design` 路径、且事件流中无同 `task_id` 的 `task_blocked` 时才 append |

> **直做时格外容易双写**：委派场景下步 1-2 由主会话执行、步 5 由 subagent 执行，两层天然隔离在不同 context；**直做时五步全在同一实例、同一轮内完成**，「刚刚已经写过一条」很容易再写一遍。落笔前按上面那句分清这条事件属于哪一层——记的是**用户说了什么**（步 1-2）还是**我做了什么**（步 5）。同一事实同时满足两层时**只记一次**，按更早的那层记。

## auto-memory（CC 门）

- **写入纪律**（叠加在官方记忆指令之上）：单条 ≤3000 字符；**指针优先**——权威文档能推出的内容不复制进记忆，只存文档推不出的判断（环境坑 / 未决项 / 拍板理由）；**工作纪实**进 changelog / 文档，不进记忆；超预算 → 先落文档再指回，不硬塞不硬砍；**scope 级指针** = 工种知识迁往 `.workframe/agent-memory/<scope>/` 后，auto-memory 每 scope 至多保留一行权威指针（如「dev 域执行经验权威见 `.workframe/agent-memory/dev/MEMORY.md`」），**不写条目级指针**。
- **清理判据**（模型只提候选，归档/删除一律用户拍板）：需求完结后其记忆压成一行指针；同模块 ≥3 条记忆合并为一条（**scope 级指针行豁免**）；已完结且文档承载的工作记忆 → 归档 = 文件移入 `.workframe/memory-archive/` + 删索引行（**文件不灭：git 可溯 + 仓库外备份**）。
