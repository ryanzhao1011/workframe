# 竞品分析技能

## 竞品分析框架

### 第一步：竞争对手分类

将竞争对手分为三类，每类精选 2-5 个，合计不超过 12 个：

| 类型 | 定义 | 示例 |
|------|------|------|
| **直接竞争者** | 同类功能、同类用户群 | 同品类 SaaS 平台 |
| **间接竞争者** | 不同功能但争夺同类用户 | 通用替代工具、相邻品类平台 |
| **替代品** | 用户现有的替代解决方案 | 人工方式、免费工具、外包服务 |

### 精选原则

- 直接竞争者：优先选择市场份额前 3-5 名
- 间接竞争者：选择用户流失去向最多的 2-3 个平台
- 替代品：选择用户访谈中被提及最多的 2-3 种方案

### 第二步：五维度深度分析

对每个竞品进行以下维度分析。信息不足时使用 `[待调研]` 占位。

#### A. 公司档案

```markdown
### {竞品名称} — 公司档案

- 成立时间：{年份}
- 公司规模：{员工数}
- 融资阶段：{种子/A/B/C/上市}
- 融资总额：{金额}
- 市场份额：{估算}
- 品牌口碑：G2 评分 {N}/5 | Capterra 评分 {N}/5
```

#### B. 用户定位

```markdown
### {竞品名称} — 用户定位

- 目标用户画像：{描述}
- 核心使用场景：{场景1}、{场景2}
- 用户痛点定位：{竞品试图解决的核心问题}
- 主要买家角色：{决策者是谁}
```

#### C. 产品功能

```markdown
### {竞品名称} — 产品功能

- 核心功能列表：
  1. {功能1}
  2. {功能2}
  3. {功能3}
- 差异化卖点（USP）：{一句话}
- 产品限制/缺陷：{已知问题}
- 技术架构（如可获取）：{描述}
```

#### D. 商业模式

```markdown
### {竞品名称} — 商业模式

- 定价结构：{免费/订阅/用量计费/混合}
- 价格区间：{最低套餐} - {最高套餐}
- 免费层能力：{有/无，限制说明}
- 分销渠道：{直销/渠道/自助}
- 营销主打：{核心营销信息}
```

#### E. SWOT 分析

```markdown
### {竞品名称} — SWOT

| | 积极因素 | 消极因素 |
|---|---------|---------|
| **内部** | S: {优势1}、{优势2} | W: {劣势1}、{劣势2} |
| **外部** | O: {机会1}、{机会2} | T: {威胁1}、{威胁2} |
```

### 第三步：四层输出物

#### 输出 A：竞争对比矩阵

按功能维度横向对比所有竞品：

```markdown
## 竞争对比矩阵

| 功能维度 | 我们 | {竞品1} | {竞品2} | {竞品3} |
|---------|------|---------|---------|---------|
| 核心功能 | | | | |
| 差异化能力 | | | | |
| 批量处理 | | | | |
| 定价（月费） | | | | |
| 免费层 | | | | |

✅ 支持 | ⚠️ 部分支持 | ❌ 不支持 | ❓ 未知
```

#### 输出 B：竞争定位图

四象限感知图，定位各竞品和我们的目标区间：

```
高质量
    │
    │    ┌─────────┐
    │    │ 目标区间 │
    │    └─────────┘
    │
────┼────────────────── 高价格
    │
    │
    │
低质量
```

- X 轴：价格（低 → 高）
- Y 轴：产品质量（低 → 高）
- 标注各竞品位置和我们的当前位置 / 目标位置

#### 输出 C：对战卡（每个直接竞品一张）

```markdown
## 对战卡：我们 vs {竞品名称}

### 竞品核心卖点
- {他们如何说服用户}

### 我们的差异化优势
1. {差异化1}
2. {差异化2}
3. {差异化3}

### 常见异议与应对
| 异议 | 应对说辞 |
|------|---------|
| "{用户常见疑虑1}" | {应对方式} |
| "{用户常见疑虑2}" | {应对方式} |

### 赢单策略
- 最佳切入场景：{什么情况下我们更有优势}
- 回避场景：{什么情况下对方更强}
```

#### 输出 D：差异化机会清单

```markdown
## 差异化机会

### 竞品共同短板（我们的机会）
1. {短板1} → 机会：{我们可以怎么做}
2. {短板2} → 机会：{我们可以怎么做}

### 无人覆盖的细分场景（蓝海机会）
1. {场景1}：{为什么没人做} → {我们的切入方式}
2. {场景2}：{为什么没人做} → {我们的切入方式}

### 建议优先级
| 机会 | 价值评估 | 实施难度 | 建议 |
|------|---------|---------|------|
| {机会1} | 高/中/低 | 高/中/低 | P0/P1/P2 |
```

### 第四步：持续监控建议

| 监控类型 | 频率 | 内容 |
|---------|------|------|
| 完整分析 | 每季度 | 全量竞品五维度更新 |
| 快速扫描 | 每月 | 竞品定价变化/新功能发布/重大新闻 |
| 信号捕捉 | 持续 | 用户反馈中的竞品提及（联动 user-feedback-analysis） |

监控结果写入 `.claude/agent-memory/pm/notes.md` 竞品动态区块。

## 执行步骤

1. 明确分析场景（全市场扫描 / 特定竞品深度分析 / 特定维度对比）；有关键疑问先提问
2. 执行竞争对手三分类，精选目标竞品
3. 按五维度逐一分析（信息不足用 `[待调研]` 占位）
4. 生成四层输出物（矩阵 + 定位图 + 对战卡 + 机会清单）
5. 在响应消息中呈现完整分析结果
6. 收到用户确认信号后落盘（归属按 skill: `document-norms` §1 判定）：绑定单模块的分析 → `projects/modules/<basic>/<sub>/research/COMP-{序号}.md`；跨模块 / 全市场的 → `projects/specs/COMP-{序号}.md`；竞品动态摘要追加至 notes.md
