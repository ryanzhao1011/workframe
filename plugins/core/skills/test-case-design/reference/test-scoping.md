# 测试选型：四档判据（详细版）

> **使用范围**：本文件是 `test-case-design` skill 第 0 步的 supporting reference。速查表（四档表 + 横切三条）已在 SKILL.md 内，本文件只补判据详解、各档反例与非代码场景的对照写法。
>
> @dev 在 `technical-design` 第 5 步（每步自测）与 `systematic-debugging` 第 5 步（回归标注）决定「这次测多深、标哪些回归点」时同样可 Read。

---

## 总体取舍

**默认起点是档 1，往上升；不是从最强验证往下降。** 多数改动是内容改动，判据要能明确告诉你「这次只需主路径读一遍 + 一致性核对」——把最强验证当默认再往下减，会让每次小改都背上不该背的成本。

**定档走三问，不是在四行里挑最像的一行**（SKILL.md 第 0 步）：三问全部问完、命中取最高档，答「是」或「说不准」都算命中。**挑最像的那一行**这个动作本身不产生「我模糊了」这个中间状态，缺省句因此拦不住它；三问把「说不准」和「是」并到同一条边上，升档成了唯一出口。

**档位是爆炸半径，不是用心程度。** 判在档 1 就按档 1 交付——多做的部分不算加分，只是把本该留给档 3/4 的力气花在了不需要的地方。**升一档最多多花半天；降一档漏掉的那次，没有人会告诉你。**

**档位由改动的性质决定，不由改动的大小决定。** 一行改动落在档 4 仍走档 4；重写一整篇文档，只要错误止于本文，仍是档 1。升档是**累加**不是替换：档 3 要做的包含档 2 的全部动作。

---

## 档 1 · 错误止于本文

**判据**：改的是内容本身，读者只有人；读错了不会让别处出错。

| 维度 | 做什么 |
|---|---|
| 类型 | 主路径读一遍 + 一致性核对 |
| 深度 | 只验「写的和实际一致」 |
| 广度 | 改动点本身 |
| 隔离 | 不需要 |

- **一致性核对指什么**：文中声称的数字、路径、字段名、步骤数、状态枚举，逐个对回它声称的来源
- **非代码场景**：一篇说明文档、一段对外话术、一条 FAQ——改完通读一遍，核对里面提到的事实还成不成立
- **边界**：文中只要出现**别处会照着做**的口径（字段名、命名约定、流程步骤），就已经不是档 1，升档 2

**反例**：把「没有代码」直接当成「档 1」。分档看的是错误会不会传播，不是有没有代码。

## 档 2 · 会传播，但没有东西会因此产出结果

**判据**：错误会传到别的文件或别的人，**但不存在任何东西会因为这次改动产出一个可比较的结果**——错了只会被某个人在某个时刻撞见。

| 维度 | 做什么 |
|---|---|
| 类型 | 档 1 + 引用面核对 |
| 深度 | + 空 / 缺失 / 异常格式 |
| 广度 | + 同族边界三问 |
| 隔离 | 不需要，但**改前先提交**（留一个回得去的点） |

**同族边界三问**（广度的判据，逐问要给出答案而不是印象）：

1. 这个事实在别处还有几份副本？
2. 这个约定还有几个使用方？
3. 这次改动周边还有哪些同类条目没碰到？

- **答不出来就是没答**——「应该没有了吧」不算答案，要说得出你搜了什么词、搜出多少处
- **与 必载片 §同一事实的多个表现层的分工**：那条管**改的时候**要不要一起改，三问管**验的时候**要覆盖多广。同一批副本，两个用途，别只做一半
- **搜的时候用改前的旧词**：用改后的新词搜，只会搜到自己刚改过的那处，剩下的副本一个都不会出现
- **非代码场景**：改一个需求口径 → 它还写在哪几份文档里？谁在按它做事？同一份文档里还有哪些条目用了同一口径？
- **边界**：三问按「同一事实的多处存在」切；`systematic-debugging` 第 3 步影响面五维按技术维度切、只适用于修 bug、产出的是影响清单。两者**互补不重合**，修 bug 时都要过

**反例**：改完自己搜一遍，确实只看见改过的那处，于是判定没有连带——因为搜的是改后的新词。三问第一问要用旧词搜。

## 档 3 · 有消费方会因你改的内容产出结果

**判据**：存在一个东西，会因为**你改的那部分内容**产出可比较的结果——通过 / 不通过、分数、diff、快照都算，不限于二元结论。

> **三条都要过，缺一条就会判错**：①判**存不存在**，不判**你现在跑不跑得动**——要 CI / 要凭证 / 要真机跑不动，那是证据问题，如实写进「不含」，不是降档理由 ②判**它对你改的那部分敏不敏感**——闸只读 frontmatter 而你改的是正文措辞，不因它升档；否则带 lint 的仓里每个文件都是档 3，档 1 与档 2 被抽空 ③**不看对象是不是代码**（见下方分界）
>
> 第 ① 条最容易反向出错：它是**降档**，而缺省句只防升档不足，防不住「我跑不动所以它不算」这种自认为已经判清楚的降档。**「可比较的结果」这个措辞**则是为评分、排名、快照差异这类非二元消费方写的——改提示词模板、改评分权重、改输出格式都落这里，按「通过/不通过」字面判会漏成档 2，而「改了提示词不跑评测」正是这类改动最典型的翻车方式。

| 维度 | 做什么 |
|---|---|
| 类型 | 档 2 + **跑真实消费方并排对照** |
| 深度 | + 边界矩阵（空 / 极值 / 并发 / 异常格式）；证据拿不到时如实标注强度 |
| 广度 | 三问 + 相邻分支 |
| 隔离 | 要写进被验对象时**用副本** |

- **并排对照指什么**：改了解析、匹配、判定逻辑时，把真实消费方跑一遍，拿它的产出和你的预期并排比
- **口径相对消费方是同宽还是更严？绝不更宽。** 更严会误报、看得见；**更宽是静默放行、看不见**——闸全绿而消费方当场炸（实证：一份被装机流程读取的目录文件，某个标题行尾多了一个空格，两道校验闸全绿，装机流程当场抛参数错误）
- **别自己另写一份判定式来验**——那是造第三套口径，两边一起错的时候仍然报绿；**也别盲目照抄消费方的实现**，那会把它的 bug 一起抄进来，同样是两边同错而闸报绿（实证：照搬「取第一个 markdown 块」的写法后，章节内混进更靠前的块时两边一起错，实测报绿）。正解是**让消费方自己跑一遍，拿它真实产出的那个值来判**——**但「复用消费方的判定式」这句有个致命读法**：复用那个「零件」不算复用，得复用**调用点的产出**，见档 4「断言钉在哪」一条
- **用副本**：需要往被验对象里写字节才能触发某个分支时，整体复制一份再动手。「就改一下、马上改回来」是最常见的破口——**改回来这个动作本身就有出错面，而它出错时你已经在真身里了**
- **非代码场景**：一份要被自动流程读取的表单模板、一份要被导入工具消费的配置——它们不是代码，但有东西会因为它们产出结果（报错、校验不通过、导入 diff），属档 3
- **边界**：消费方报绿不等于验过。绿只证明这一次没触发；「它错的时候会不会红」是档 4 的问题

**反例**：配置文件不是代码，于是按档 2 处理；而它每次装载都被脚本读取并校验，一个字段拼错就整条链路失败。**分档看有没有消费方，不看文件像不像代码。**

## 档 4 · 被改的东西自己就是判据

**判据**：改的对象的职责本身就是「判断别的东西对不对」——测试、校验、断言、自查清单、评分标准、验收口径，**不论靠机器还是靠人执行**。

> 档 4 按**对象职责**判定，与档 2/3 那条「有没有消费方」是两个独立维度：一份纯人工执行的自查清单在第 2 问上答否，仍然是档 4。

| 维度 | 做什么 |
|---|---|
| 类型 | 档 3 + **用它自己的失败方式打一遍** |
| 深度 | + 先跑基线确认是绿的 + 结论的反面要能被打出来 |
| 广度 | 三问 + **同契约的其他实现** |
| 隔离 | **必须副本** |

- **用它自己的失败方式打一遍**：造一个它**应该**判失败的输入，确认它真的判了失败。突变粒度与构造不出时的出口见必载片同名节
- **先跑基线**：动手前确认「现在是绿的」，否则改完出问题分不清是不是自己带来的
- **反面要能被打出来**：交付里写「已验证 X」时，说得出「如果 X 不成立，会在哪一步暴露」。说不出，那句话就只是「这一次没触发」
- **同契约的其他实现**：写新判定式前先找同契约的既有实现——找齐的判据与交叉关系的处理见必载片 §同一事实的多个表现层
- **`==` 还是 `⊆` 由被检对象的语义定，不一刀切**：判据一句话——**漏一个是否构成真实功能缺陷**。是（「要求列全名录」「驱动遍历」这类）→ `==`；`⊇` 只咬「少」，会把「多」静默吞掉，而 `⊆` 是恒绿方向，把被检集合删空就全过。否（「这片区域整体归我」的圈地语义，只挑代表性 token 做存在性探测）→ 存在性 / `⊆`；要求它与某份登记名录逐个相等，等于把通配降级成手写清单，正常改动都会报红，那是假红。**两个方向的错法不同**：该 `==` 写成 `⊆` 是恒绿假闸，该 `⊆` 写成 `==` 是假红。现成对照在 `module-close-check` 里——code-map 的 `source_paths` 与 `code_paths` 比 `==`（名录语义），`code_paths` 的 glob 展开只判「≥1」（圈地语义）
- **写容器级下限断言前，先实核被检对象的「每容器几处」**：「清单里每个容器至少贡献 1 处」这类下限，**只在「每容器恰 1 处」时才等价于站点级**；一旦某个容器装了 N 处，它就退化成「只要还剩 1 处就绿」。套这个形状之前先跑一次分布统计（容器 → 处数）。退化区间由另一道闸接管时，在注释里写明这个前提——**那道闸被削弱或移除，本闸的下限断言就没了依据**
- **断言钉在哪**：钉在**消费方在真实路径上产出的那个值**上，不是钉在**它声称使用的那个零件**上。先看被检对象是哪一类——**文本资产**（rules / 模板 / 文档正文 / 提示词）用存在性断言**成立**，文本本身就是交付物，没有「调用点」这一层，写在文件里就是生效；**代码符号**（常量 / 函数 / 字段名 / 正则）用存在性断言**不成立**，定义 ≠ 被调用。**修法按闸站在哪一侧分两种**：闸在**静态侧**（只读消费方源码）→ 断言「该符号在那个函数体内**被引用**」（宽收候选、严判求证、差集非空即红），别只断言它存在；闸在**动态侧**（跑得动消费方）→ **直接读流水线产出的那个值，绝不在断言里重跑一遍判定式**——重跑等于闸自己成了第三套口径，正是档 3「别自己另写一份判定式」要防的东西（实测：重跑版在「调用点被换掉」的注入下命中 0/12，读产物版命中 12/12）
- **改的是判据或规则本身 → 回套全部既有条目。** 新判据只在新条目上跑一遍不算数：既有条目是按旧判据落的，改判据等于把它们全部重判一次而没人去看。**实证**：某次改了一条判定规则后回套，15 条既存条目里真的有需要改判的。**这一条比它看上去贵得多，也正因为贵才总被跳过**——跳过的代价是判据与它管着的存量从此不一致，而不一致的那部分不会报错
- **改的是扫描面或口径 → 逐格复核有无判定被放宽。** 扩扫描面、放宽正则、加一个 `or` 分支，都可能让**原来会红的输入现在变绿**。**实证**：某次扩扫描面后逐格复核，查出一格判定被静默放宽。做法是把改动前后的判定结果按格对照，**只看新命中的那些格不够**——被放宽的那一格恰恰是「原来红、现在不红」，它不在新命中里
- **非代码场景**：写 PRD 完整性自查清单、写输出质量的评分标准、写一份验收口径——都是在写一个检查，都落这一档
- **边界**：本档只管「测到什么程度」。**怎么造探针、怎么做变异**不在这里——那是手法，跟着上面两条指针走

**反例**：断言引用了某个常量，以此证明消费方在用它；把消费方的调用点换成内联副本、常量留成孤儿，断言**仍然全绿**。**零件在货架上完好，不等于装到机器里了。**

## 两条分界

### 档 2 / 档 3：看有没有东西因你的改动产出结果，不看是不是代码

按对象类型分会把两类判反：有校验脚本读取的配置文件是档 3；被另一份文档引用、但没有东西会因此产出结果的措辞是档 2。

### 档 4 单列：失败模式根本不同

前三档改错了会**炸**，有信号；档 4 改错了**静默不报**，而且此后所有依赖它的判断跟着一起瞎。这是唯一需要用失败方式自证的一档。

## 横切三条（不分档，全适用）

### 每项验证注明证据强度

三级：①真实实跑 ②契约文档 / 官方规范 ③等价替身推演。**拿不到就如实写「未验」，别把③记成通过**——③ 证的是「按规格应该如此」，不是「实际如此」。

> 「已验证」必须说清**验了哪几项、不含哪几项**，以及「不含」不能写恒真命题——完整口径在必载片 §陈述可证伪。本节只补它没有的那一层：**同样在「含」里的项，证据强度可以差两级**，不注明就等于把 ③ 冒充成 ①。

### 打回重做要三版并列

复验返工时并列三版：**原始基线 / 被打回版 / 返工版**。只比两版，会把「返工新引入的」和「首轮就在的」糊成一片——返工引入的新问题最容易从这个缝里漏过去。

### 方向错阻断，尺度严登记

被验对象是判定逻辑时，缺陷的**方向**比严重度更决定处置：假绿（该拦的没拦）阻断，假红（多拦了，方向 fail-safe）登记不阻断。完整判据与分级写法见 skill: `code-review` 第 3 步。
