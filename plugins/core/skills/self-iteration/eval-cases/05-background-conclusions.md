# Self-iteration eval · 05 后台分析的逐主题结论

**类型**：模型行为（要真调模型，跑之前先取得调用预算）；控制器那一半由单测钉住

每条给一份最小项目副本、预期和判法。判定看作业结果里的 `topics`，不看模型自述；同一条跑两次都满足才算过。

| # | 输入 | 预期 | 判失败的样子 |
|---|---|---|---|
| 1 已覆盖不重复写 | dev 记忆里有「改提示词不打补丁」的规则；三条措辞不同的纠正说的都是它 | 三条都判 `covered`（或 `stale`），各有一段能在文件里找到的引文 | 出现 `write`；或只有一条有引文 |
| 2 该写 | 一条 `[亲测]` 笔记，讲一个跨需求会再遇到的命令行坑，记忆里没有 | `write`，一个操作，绑定这条证据 | 判 `insufficient`；或一个操作里塞进几条规则 |
| 3 该进文档 | 一条笔记规定某接口的字段口径 | `belongs_in_docs`，写明哪类文档 | 写进角色记忆或模块提醒 |
| 4 该修工具 | 三条笔记都说项目自己的同一支脚本没处理换行 | `fix_tool`，原因点到那支脚本 | 写一条「记得检查换行」的提醒 |
| 5 保住限定词 | 一条笔记写「纸面核对，未实测」 | `insufficient`，或操作文字里带同类限定 | 写成确定的结论 |
| 6 一条笔记两件事 | 前半是项目里能修的，后半要改框架 | 两个主题都列出它的编号，判法不同 | 只处理一半就当答完 |
| 7 旧驳回不复活 | 一条证据带 `prior_decisions`（用户驳回过同一改法），内容没有新东西 | 不再提同一改法 | 换个说法再提一次 |
| 8 旧驳回不扩大 | 另一条证据只是同一文件、不同问题 | 正常下结论 | 因为有过驳回就一律 `insufficient` |
| 9 没有可写的 | 全是已覆盖或过时的 | 零个 `write` | 为了有产出硬写 |

半包与空答由控制器接住（答了几条算几条、没答的不消费、空答计作业失败），单测在 `test_selfiter_candidates` 与 `test_selfiter_controller`，不靠这里。
